# 零人工审批更新管线

这套管线的原则不是“自动相信”，而是“自动发布可追溯证据，并把证据强度展示给读者”。

`sources.json` 是采集入口配置，不是按权威性筛选的媒体白名单。支持 RSS、国家电影局备案，以及新增的微博官方 CLI 网关适配。来源可标为官方、媒体或社媒线索；匹配标题、账号认证、转发数量都不会自动将内容升级为已证实。小红书本轮不接入采集。

2026-09-23：按用户要求暂时跳过微博全网搜索及账号时间线 API。对应来源仍停用，自动任务不注入微博凭证，也不请求授权；以后明确恢复时再参考 [微博接入说明](WEIBO_SETUP.md)。2026-09-30 新增的淘票票、灯塔指定官方账号是无需登录的新浪公开展示页，只读取这两个账号的公开帖子，不开启全网微博抓取。

运行：

```bash
python3 automation/brief_pipeline.py --sources automation/sources.json --output generated/latest.json --store generated/collected_items.json
```

采集后先增量保存到 `generated/collected_items.json`，再按日期和相关性生成页面。旧条目不会因为本轮未出现而丢失；发布时间不明或过时条目仍保留在库中，但不冒充今日新闻。英文条目可进入首页，翻译失败时保留原文。损坏的旧库会显式报错，不会被空库覆盖。

翻译后运行 `editorial_brief.py`：同日、同地区、同作品且属于同一类进展的稿件合并为一件事；票房不同节点、定档与上映等不同进展仍分开。首页优先显示有明确新信息的提要，纪念日回顾、未公布结果的预热和促销帖不挤占首页。所有当天原始条目保存在 `source_items`，未进首页的事件在 `more_items`，低信息量条目在 `filtered_items`；页面底部可以查看其原始链接。合并只是阅读整理，不会因为来源数量增加就自动认定事实已核实。

`errors`、`source_statuses` 和 `market_coverage` 用于区分待授权、无来源、请求失败和查询窗口受限；某个来源失败不影响其他来源。完整的采集库只保存在项目数据目录，网页端仍输出当天可展示的条目。

`policy.render_languages` 允许中、英文原始资讯进入首页。英文标题和摘要会在采集后尝试通过 Cloudflare Workers AI 翻译成简体中文，保留原始标题、摘要、链接和“机器翻译”标记；凭证、权限或服务不可用时直接展示英文原文，不再静默丢弃。翻译结果缓存在 `generated/translation_cache.json`，原始采集库保持不变。首页按原始发布时间的北京时间自然日展示；`allow_carry_forward=false`，不混入之前的新闻。空板块根据实际来源状态提示“暂未收录”或“采集来源尚待补充”，不等同于该地区真的没有新闻。

目前提供采集、持久保存、去重、新鲜度过滤、来源标注和线上发布核验。仍需继续完善：

1. 持续扩充公开来源、补全文搜索发现，并监测自动翻译的译名质量；微博、小红书暂不接入，不以社媒授权为其他改造的前提。
2. 现有 GitHub Actions 保留北京时间 10:10 和 18:00 的计划，但不保证准点；需要进一步完善迟到监控和长期授权维护。部署继续使用原 Cloudflare Pages 项目，不新建地址。

语言模型如用于翻译或摘要，只能改写来源已有信息；渲染页必须保留原始链接、证据等级和生成时间。

四个市场是覆盖监控口径，不是发布闸门：任一市场没有条目不影响其他市场更新。只有所有来源采集失败或发生运行错误才返回非零退出码；至少一个来源成功但今天零条时，可生成如实说明的空状态，不回填昨天。
## 中文来源策略

收录可采集、可回链的相关资讯，不因为来源可信度不高而拒绝收录。显示“官方发布”“媒体报道”“社媒线索”，保留原始发布时间、来源名称和原文链接；这些是来源标注，不是事实背书。

- `max_age_hours` 为 120 小时，用于后台候选池；持久库不随这个窗口删除历史。网页端仅使用北京时间当天的消息；采集层不按地区截断，首页提要按阅读范围筛选，其余当天线索仍可追溯。
- `电影界` 的电影新闻、电视与剧集、行业资讯栏目用于扩大中文覆盖；它们是媒体线索，不会被标记为“官方确认”。短剧栏目及以短剧为主题的条目不展示；电影/长剧报道仅顺带讨论短剧时不会整条删除。
- 影人影事的影视关键词改为检查标题和摘要；取消电视与剧集栏目中“舞台/节目”等一刀切排除。行业关键词仍用于相关性筛选，被过滤的原始条目保留在库中。
- 海外英文来源除 Variety 电影外，增加 Variety 剧集、Deadline 电影与剧集、The Hollywood Reporter 电影与电视 RSS；它们是来源入口，不代表所有新闻已得到多方证实。IMDb NewsDesk 主要汇聚这些原媒体资讯，不作为独立确认来源。
- 自动翻译仅作用于原始标题和摘要，不翻译或改写发布时间、来源、证据等级。Cloudflare Workers AI 需要令牌包含 Workers AI Read/Edit 权限；优先使用 `CLOUDFLARE_AI_TOKEN`，未设置时尝试现有 `CLOUDFLARE_API_TOKEN`。没有权限也照常发布英文原文，`stats.translation.provider_status` 会给出原因。不能把翻译当成事实核实。
- 每个地区内固定按 **院线电影 → 电影备案项目 → 渠道待确认电影 → 网络电影 → 剧集 → 其他行业线索** 排列，同类型再按发布时间倒序。
- 保留国家电影局备案解析和明细展示能力。现行全局 `allow_carry_forward=false`，因此来源原有的 30 天延续展示参数不再对首页生效。备案公示仍保留原日期，不暗示定档或取得公映许可。
- 电影内容按发行渠道单独标记为 **院线电影 / 网络电影 / 电影·渠道待确认**。只有标题、摘要或信源配置提供明确依据时才判为院线或网络电影；不会仅凭“电影”二字猜测。中国内地版面与容量截断均优先保留院线电影，其次为渠道待确认电影，再到网络电影、剧集和其他行业线索。
- 当天 RSS 卡片会自动提取来源图片，并保留“物料、预告状态、信息验证、原始信源”模块；没有可靠视频时明确显示“预告片暂未收录”。首页不再追加往日海报或预告卡片。

## 2026-09-23 公开来源扩展

增加中新网文化、中央社娱乐、香港电影博客、香港电台相关报道、时光网、新京报娱乐、人民网影视产业报道。共 14 个入口、10 家发布主体，包含既有电影界的 5 个栏目，不能把入口数当成独立媒体数。香港电影博客标为“行业观察”，不以媒体知名度作收录门槛。

新页面适配器保留原始日期、短摘要、来源图片及原站提供的视频；相对时间须到原文读取，详情失败保留列表记录但不编造发布日期。RSS 不再提前截断，正文中的图片可提取，但不复制整篇文章。中央社 RSS 仅按其目录声明的个人非营利用途使用；商业化前需另行核实授权。

本地首轮真实测试：653 条原始记录入库，7 条进入 9 月 23 日中文首页；13/14 个入口成功，香港电台一次连接失败后单独复测恢复。时光网、新京报本次列表最新为 9 月 22 日；电影界多个栏目最新为 9 月 20 日，国际栏目为 8 月 21 日。网页成功返回不代表有今日新闻。`source_statuses` 分别记录抓到条数、今日条数、最新原始时间、无日期条数与连接状态。

临时连接故障及 502/503/504 最多重试一次，403 等访问限制不重试；证书问题不关闭校验。本机 Python 若缺失默认根证书，可仅对本次命令使用系统证书：

```bash
SSL_CERT_FILE=/etc/ssl/cert.pem python3 automation/brief_pipeline.py --sources automation/sources.json --output generated/latest.json --store generated/collected_items.json
```

此路径适用于当前 macOS 本机；GitHub Actions 使用运行环境默认可信证书。部署后 `verify_deployment.py` 回读线上 JSON 和 HTML，核对本次数据、日期和新闻标题；不会把“上传成功”直接当成“用户已看到新版”。定时任务仍可能被 GitHub 延迟，尚不承诺准点。

## 小红书内容包

`xhs_generate.py` 会从 `generated/latest.json` 的未截断 `xhs_items` 池中优先选择北京时间前一天的条目；昨日为空时，可回退到本轮最近一个有内容的日期。单一来源内容照常生成并标记为“待确认”，不会因为尚未被多源确认而空更。程序生成固定 3:4 多图、发布文案与 `manifest.json`；状态只显示为小号“已确认”或“待确认”，不会把验证信息做成视觉主角。详细运行和发布边界见 `XHS_WORKFLOW.md`。
